# Garment low-LoD candidate

`finalAccepted=false`, `physicsPass=false`, `visualPass=false`. This is an isolated package for review and solver experiments; it is not installed in the current runtime.

Base: `../garment-production/assets/component.json` and `.bin`. The low solver has 320 outer points (9 rows) and 352 lining points (10 rows). Each has 48 points at both open boundaries and 32 points on interior rings; zipper triangles connect different ring counts without T-junctions. Sampling follows the existing canonical angular/vertical parameterization. The 48 waist points per layer are hard pelvis pins. High render geometry, original UV, Float32 color, material and source22 skin arrays are byte-identical to the base component. Source and package hashes and array checks are in `reports/verify.json`.

The high shell is bound to the nearest solver triangle using unclamped plane barycentrics plus signed normal offset. Negative coordinates are intentional: outer 398 vertices, minimum -0.18994; lining 415, minimum -0.10635. Float32 reconstructed rest maximum component error is at most 5.96e-8 sourceunit for both bind and neutral; this is a static reconstruction result, not proof of dynamic quality. Extrapolation can amplify local deformation and requires downstream consumers to preserve signed barycentric weights. The current runtime adapter and shader appear to pass signed Float32 values directly, but this candidate has not been run through that runtime.

Outer and lining maximum absolute normal offsets are 0.03085 and 0.01878 sourceunit, about 10.80 and 6.57 mm under the existing 0.35 m/sourceunit scene calibration. These offsets exceed the original high-resolution component and require special attention for collision coverage and dynamic behavior. No claim is made that a proxy envelopes the actual deforming rendered cloth.

Each low mesh is connected, has 96 boundary edges (48 at each open end), no nonmanifold or orientation-conflict edges and Euler characteristic zero. The neutral strict intersection audit of both solver surfaces and the actual mapped high shells finds no self or interlayer crossings; minimum sampled bidirectional vertex-to-triangle separation is approximately 11.53 mm for solver and 10.38 mm for render. The audit excludes tangencies/coplanar crossings and does not establish continuous collision or edge-edge minimum separation.

Lumped areas are proportionally scaled so their total equals the corresponding source component's total area, allowing an area-weighted solver to preserve its total mass. Actual mass, forces and material calibration remain the solver's responsibility. In particular, per-hinge stiffness from the old mesh must not simply be copied and called the same material; calibrate bending by geometric energy at matching curvature, and independently validate stretch, timestep, interactions and contact.

`index.html?compare=1` compares the original production high shell with the high shell actually reconstructed from the LoD mapping at rest, in the same character and renderer. It is a static inspection, with no physics. Browser/GPU review and Godot integration remain pending. `build.mjs`, `verify.mjs` and `audit-neutral.mjs` reproduce the package and checks without changing the production component. See `reports/build.json`, `reports/verify.json`, and `reports/neutral-intersection.json` for measurements and limits.
